# Поток данных

От файла выгрузки до витрины признаков, с точками отказа и точками прослеживаемости.

```mermaid
flowchart TB
    F["Файл выгрузки"]

    subgraph ingest["Приём"]
        UP["Загрузка через API<br/>проверка типа и размера"]
        LAND["Landing в MinIO<br/>неизменяемая копия + checksum"]
        REC["DataImport в PostgreSQL<br/>статус PENDING"]
    end

    subgraph process["Обработка в воркере"]
        PROF["Профилирование<br/>типы · пропуски · диапазоны"]
        VAL["Валидация по контракту<br/>структура · типы · домен · конвейер"]
        ANON["Псевдонимизация<br/>удаление прямых идентификаторов"]
        CLEAN["Очистка<br/>дубликаты · типы · справочники"]
        TRANS["Трансформация<br/>каноническая модель"]
    end

    subgraph storage["Хранение"]
        CAN[("ClickHouse<br/>канонический слой")]
        AGG[("ClickHouse<br/>предагрегаты")]
        FEAT[("ClickHouse<br/>витрина признаков")]
    end

    subgraph out["Результаты"]
        DQ["Отчёт качества<br/>MinIO + PostgreSQL"]
        FRESH["Свежесть данных<br/>PostgreSQL"]
        REJ["Отклонённые строки<br/>с причинами"]
    end

    F --> UP --> LAND --> REC --> PROF --> VAL

    VAL -->|контракт нарушен| FAIL["Импорт отклонён<br/>статус REJECTED"]
    VAL -->|найдены прямые<br/>идентификаторы| FAIL
    VAL -->|строки отклонены| REJ
    VAL -->|принято| ANON --> CLEAN --> TRANS --> CAN --> AGG --> FEAT

    VAL -.-> DQ
    CLEAN -.-> DQ
    CAN -.-> FRESH

    style FAIL fill:#fdecea,stroke:#c0392b
    style ANON fill:#fdf0e6,stroke:#c47a3d,stroke-width:2px
```

## Ключевой порядок

Псевдонимизация выполняется **до** очистки и до любой записи в аналитическое хранилище. Прямые идентификаторы существуют только в оперативной памяти воркера и в landing-копии с ограниченным сроком хранения.

Обратный порядок — сначала загрузить, потом обезличить — означает, что персональные данные хотя бы кратковременно оказываются в аналитическом хранилище, откуда они попадут в резервные копии и реплики.

## Прослеживаемость

```mermaid
flowchart LR
    IMP["import_id<br/>contract_version"] --> CAN["Канонические записи"]
    CAN --> AG["Агрегаты<br/>окно расчёта"]
    AG --> FE["Признаки<br/>feature_set_version"]
    FE --> FC["Прогноз<br/>model_version"]
    FC --> SG["Сигнал"]
    SG --> EX["Объяснение"]
```

Требование: для любого числа, показанного пользователю, система должна назвать импорт, версию контракта, версию набора признаков и версию модели. Поэтому идентификаторы переносятся по всей цепочке, а не теряются на первом агрегате.

## Точки отказа и реакция

| Точка | Условие | Реакция |
|---|---|---|
| Приём | Неверный тип или превышен размер | Отказ до сохранения |
| Валидация структуры | Нет обязательного поля | Отклонение всего импорта |
| Валидация строки | Неверный тип или домен | Отклонение строки с причиной |
| Обнаружение идентификаторов | Найдены прямые идентификаторы | Остановка при строгом режиме |
| Конвейерная проверка | Аномальный объём | Требуется подтверждение администратора |
| Идемпотентность | Тот же файл и период | Повторная загрузка не создаёт дублей |
