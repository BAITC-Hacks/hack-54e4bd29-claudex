# Architecture Decision Records

Каждый ADR фиксирует одно значимое решение: контекст, варианты, выбор, последствия и условия пересмотра. Принятый ADR не редактируется задним числом — его заменяет новый со ссылкой на предыдущий.

## Формат

| Раздел | Содержание |
|---|---|
| Статус | Предложен, Принят, Заменён, Отклонён |
| Контекст | Обстоятельства, в которых потребовалось решение |
| Варианты | Рассмотренные альтернативы с оценкой |
| Решение | Что выбрано |
| Последствия | Что становится проще, что сложнее, чем платим |
| Пересмотр | При каких условиях решение перестаёт быть верным |

## Когда нужен новый ADR

Новое решение фиксируется отдельным ADR, если оно меняет границы модулей, добавляет или убирает компонент инфраструктуры, меняет модель доступа, меняет целевую переменную или метрику модели, вводит новый источник данных либо принимает осознанный технический долг со сроком возврата.
