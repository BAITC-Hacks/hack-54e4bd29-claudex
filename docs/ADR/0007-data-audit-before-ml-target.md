# ADR-0007. Data Audit до выбора целевой переменной

**Статус:** Заменён [ADR-0014](0014-forecast-target-deferred-after-audit.md)
**Дата:** PHASE 0

## Контекст

Реальная структура выгрузок ИС БГ, ЭРСБ и ЕИП на момент проектирования не изучена. Известны только предполагаемые области содержания: направления, ожидающие, отказы, пролеченные случаи, лабораторные исследования.

Неизвестны критические вещи: гранулярность записей, наличие и смысл временных меток, глубина истории, регулярность обновления, устойчивый идентификатор организации, доля пропусков, наличие персональных данных, сопоставимость справочников между источниками.

Соблазн понятен: зафиксировать целевую переменную сейчас, спроектировать признаки и приступить к модели. Но каждый из трёх кандидатов требует полей, существование которых не подтверждено.

## Варианты

**Выбрать цель по предположению.** Даёт немедленное движение. Риск: при расхождении с реальностью переделываются признаки, конвейер, схемы хранения и интерпретация. Худший вариант — обнаружить расхождение после написания кода обучения.

**Ждать данные, ничего не делая.** Безопасно и неприемлемо: срок ограничен.

**Спроектировать контракты и отложить выбор цели.** Работа идёт по всем направлениям, кроме тех, что зависят от неизвестного.

## Решение

Целевая переменная не фиксируется до завершения Data Audit. Вместо этого:

**Создаются контракты наборов данных** в `data_pipeline/contracts/` — машиночитаемые описания ожидаемой структуры с версионированием. Код пишется под контракт, а не под конкретный файл.

**Data Audit выделен в обязательный шаг** перед PHASE 5. Он отвечает на перечень вопросов из [DATA_ARCHITECTURE.md](../DATA_ARCHITECTURE.md#41-что-выясняется) и завершается отчётом о пригодности данных для каждого кандидата цели.

**Кандидаты перечислены с условиями реализуемости**, но ни один не выбран:

| Кандидат | Что должно подтвердиться |
|---|---|
| `incoming_flow(t+n)` | Событие направления с датой и организацией назначения |
| `queue_size(t+n)` | Регулярные снимки очереди либо восстановимость из событий |
| `waiting_time(t+n)` | Дата постановки и дата госпитализации в одной записи |

Предварительная оценка: `incoming_flow` наиболее вероятно реализуем, поскольку событийные данные обычно содержат дату. Это гипотеза, а не решение.

**Выбор цели фиксируется отдельным ADR** после Data Audit и записывается в `FORECAST_TARGET`.

**Всё, что не зависит от цели, реализуется параллельно:** инфраструктура, доменная модель, RBAC, аудит, конвейер импорта, аналитика, правила Signal Engine, интерфейс.

## Последствия

Становится проще: работа не блокируется отсутствием данных. Появление реальной структуры приводит к изменению контракта, а не к переписыванию системы. Границы модулей позволяют подключить конкретную цель в одном месте.

Становится сложнее: часть кода пишется против интерфейсов без работающей реализации. Требуются заглушки и синтетические данные для разработки.

Чем платим: риском, что Data Audit покажет непригодность всех трёх кандидатов. Этот риск принят заранее, и реакция на него определена: **система остаётся полезной без прогноза**. Мониторинг, правила и статистические сигналы работают независимо от ML. В этом случае Signal Engine реализуется на двух источниках из трёх, а прогнозный блок показывает явное объяснение недоступности.

Это прямое следствие [ADR-0008](0008-signal-engine-three-sources.md): три независимых источника сигналов спроектированы в том числе ради устойчивости к отсутствию ML.

## Запреты

Пока Data Audit не завершён:

- не придумывать структуру полей и не писать код под воображаемую схему;
- не обучать модель на синтетических данных, выдавая результат за оценку качества;
- не фиксировать метрику качества — она выбирается после цели;
- не подгонять цель под метод, если первый выбор дал плохой результат.

Последний запрет существенен: переопределение цели после плохого результата — это подгонка задачи под инструмент, и она делает оценку качества недостоверной.

## Пересмотр

ADR заменяется новым сразу после завершения Data Audit. Новый ADR фиксирует выбранную цель, обоснование выбора, метрику качества и условия, при которых прогноз не строится.
