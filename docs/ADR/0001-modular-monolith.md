# ADR-0001. Модульный монолит вместо микросервисов

**Статус:** Принят
**Дата:** PHASE 0

## Контекст

MedSignal объединяет несколько разнородных областей: справочники и доступ, аналитику временных рядов, обработку входных данных, машинное обучение, симуляцию сценариев. Соблазн разделить их на сервисы возникает сразу.

При этом границы предметной области ещё не проверены практикой. Структура данных не изучена, набор показателей не зафиксирован, модель Signal Engine будет уточняться по обратной связи. Команда невелика, срок MVP ограничен.

## Варианты

**Микросервисы с самого начала.** Независимое масштабирование и развёртывание каждой части. Но цена — сетевые границы, распределённые транзакции, согласованность справочников между сервисами, отдельные конвейеры развёртывания, сложная локальная разработка. Всё это оплачивается до того, как станет ясно, где реальные границы. Неверно проведённая граница между сервисами стоит на порядок дороже неверно проведённой границы внутри монолита.

**Монолит без внутренних границ.** Быстрый старт, но через несколько месяцев бизнес-правила расползаются по контроллерам и компонентам, а зависимости становятся неразрывными. Это наиболее вероятный исход при работе под сроком.

**Модульный монолит.** Одно развёртываемое приложение с явными внутренними модулями и проверяемыми правилами зависимостей. Границы существуют, но проходят внутри процесса и потому дёшевы в изменении.

## Решение

Модульный монолит. Backend — одно приложение FastAPI, разделённое на слои `api`, `business`, `repositories`, `models` и на доменные модули внутри `business`.

Границы обязательны и проверяются автоматически: конфигурация `import-linter` в CI запрещает импорт `fastapi` внутри `business`, импорт `business` из `repositories`, импорт `backend.app` из `ml`, обращение к внутренностям чужого доменного модуля в обход его публичного сервиса.

Правило взаимодействия между доменными модулями: только через публичный сервис. Общие типы — в `business/shared`. Циклы запрещены.

## Последствия

Становится проще: локальная разработка одной командой, единая транзакция там, где она нужна, рефакторинг границ без изменения контрактов между процессами, отладка по одному `request_id` без распределённой трассировки.

Становится сложнее: невозможно масштабировать отдельную часть независимо — масштабируется приложение целиком. Частично это снимается выносом тяжёлых операций в воркеры, которые масштабируются отдельно.

Чем платим: дисциплиной. Границы в монолите не защищены сетью, поэтому их нарушение технически возможно. Именно поэтому проверка границ включена в CI и ломает сборку — граница, которую не проверяет машина, разрушается за несколько недель.

## Пересмотр

Выделять сервис имеет смысл, когда одновременно выполняются несколько условий: часть системы требует принципиально иного профиля масштабирования, её цикл релиза расходится с остальными, и граница модуля устойчива в течение нескольких месяцев без изменений.

Наиболее вероятный первый кандидат на выделение — ML-инференс, поскольку он уже отделён портом `ForecastPort` ([ADR-0005](0005-ml-separation.md)) и его вынос не затронет бизнес-код.
