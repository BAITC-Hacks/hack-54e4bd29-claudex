# ADR-0008. Три независимых источника Signal Engine

**Статус:** Принят; deduplication и stale behavior заменены ADR-0017
**Дата:** PHASE 0

## Контекст

Signal Engine — ядро продукта: он превращает данные в повод для действия. От его устройства зависит, будет ли система полезна.

Два очевидных подхода имеют существенные недостатки.

Только правила: прозрачно и предсказуемо, но требует заранее знать пороги. Пороги неизвестны — организации различаются по масштабу и профилю, и единое значение либо порождает шум для малых, либо молчит для крупных.

Только ML: адаптивно, но полностью зависит от наличия данных и качества модели. Пока цель не выбрана ([ADR-0007](0007-data-audit-before-ml-target.md)), ML-источник не существует. Кроме того, ML не обнаруживает проблему с самими данными: устаревшая выгрузка для модели выглядит как обычный вход.

## Варианты

**Один источник.** Проще в реализации, но система становится либо негибкой, либо неработоспособной без модели.

**Два источника: правила и ML.** Пропускается важный класс — отклонения от собственной нормы организации без заранее заданного порога.

**Три источника с фиксированным порядком.** Каждый покрывает свой класс проблем.

## Решение

Три независимых источника, выполняемых в фиксированном порядке.

| Источник | Класс проблем | Работает без ML | Пример |
|---|---|---|---|
| `RULE_BASED` | Детерминированные условия: свежесть, полнота, явные пороги | Да | Данные не обновлялись дольше допустимого |
| `STATISTICAL` | Отклонение от собственной нормы организации с учётом сезонности | Да | Аномально высокая доля отказов |
| `ML_BASED` | Прогнозируемое развитие ситуации | Нет | Модель прогнозирует существенный рост очереди |

### Почему именно такой порядок

Правила выполняются первыми, потому что их результат определяет допустимость остальных evaluator. Если правило обнаружило устаревшие данные, создаётся `DATA_STALE`, а statistical spike evaluator и stale forecast signal возвращают `SUPPRESSED`. Обратный порядок мог бы создать operational signal на заведомо неактуальных данных.

### Ключевые свойства

**Источники независимы.** Отказ одного не останавливает остальные. Система без обученной модели продолжает предупреждать по правилам и статистике.

**Статистика опирается на собственную историю организации.** Сравнение с другими организациями порождает ложные срабатывания: крупная больница всегда выглядит выбросом на фоне малых.

**ML-источник срабатывает только при валидном прогнозе.** Прогноз хуже baseline не порождает сигнал `OVERLOAD_FORECAST`.

**Проблема данных отделена от проблемы нагрузки.** Тип `DATA_STALE` существует отдельно, чтобы сбой выгрузки не выглядел как рост очереди.

**Дедупликация выполняется после всех источников.** Первоначальное решение об
обновлении активного Signal заменено replay-safe политикой
[ADR-0017](0017-signal-evaluation-and-deduplication.md): точный replay
пропускается, новый watermark создаёт новую evidence record.

**Минимальная длительность условия обязательна.** Единичный всплеск не является сигналом.

## Последствия

Становится проще: система полезна с первого дня, до появления модели. Классы проблем разделены, и каждый решается подходящим методом. Отсутствие ML не блокирует продукт.

Становится сложнее: три механизма вместо одного, необходимость согласования между ними, риск дублирования сигналов по одной причине из разных источников. Компенсация — общий этап дедупликации и слияния.

Чем платим: настройкой. У каждого источника свои параметры, и их согласование требует обратной связи от пользователей. Параметры вынесены в конфигурацию и версионируются, чтобы изменение поведения было прослеживаемым.

## Связь с устойчивостью системы

Это решение — основная мера против риска непригодности данных для ML. Если Data Audit покажет невозможность выбрать проверяемую цель, Signal Engine работает на двух источниках, а продукт сохраняет смысл: обнаружение, объяснение, решение человека и контроль остаются на месте. Теряется только прогнозная составляющая.

## Пересмотр

Добавление четвёртого источника рассматривается при появлении класса проблем, не покрываемого тремя существующими. Наиболее вероятный кандидат — корреляционный источник, обнаруживающий связанные отклонения в нескольких организациях региона одновременно. Он требует накопленной статистики совместных срабатываний и отложен до пилота.
