# ADR-0011. ForecastPort поддерживает синхронный и фоновый инференс

**Статус:** Принят
**Дата:** PHASE 1
**Уточняет:** [ADR-0005](0005-ml-separation.md) и правило фоновой обработки из [ADR-0004](0004-background-workers-celery.md)

## Контекст

ADR-0004 установил, что тяжёлые операции выполняются в фоне, и перечислил инференс среди них. ADR-0005 зафиксировал обращение к ML через порт `ForecastPort`.

Формулировка «инференс выполняется в фоне» была прочитана как архитектурный запрет на синхронный вызов модели. Такой запрет чрезмерен и вреден.

Не всякий инференс тяжёл. Предсказание для одной организации на загруженной в память модели градиентного бустинга занимает единицы миллисекунд. Запрет на синхронный вызов в этом случае означает, что пользователь, открывший карточку организации, получает `202 Accepted` и вынужден опрашивать результат ради расчёта, который уложился бы в обычный ответ.

Важно и то, что запрет фиксирует решение на уровне архитектуры, тогда как это вопрос бюджета времени ответа — величины измеримой и меняющейся.

## Решение

Архитектурного запрета на синхронный инференс нет. Способ выполнения определяется характером операции и бюджетом времени ответа.

| Операция | Способ | Причина |
|---|---|---|
| Обучение модели | Только фоновый | Минуты и более |
| Массовый прогноз по многим организациям | Только фоновый | Объём работы не ограничен сверху |
| Регулярный прогноз по расписанию | Только фоновый | Инициируется расписанием, не пользователем |
| Тяжёлое объяснение, требующее пересчёта вкладов по выборке | Только фоновый | Сопоставимо по стоимости с обучением |
| Единичный быстрый прогноз | Может быть синхронным | Укладывается в бюджет ответа |

### Правило допустимости синхронного вызова

Синхронный инференс допустим, если одновременно выполняются условия:

| Условие | Проверка |
|---|---|
| Операция ограничена сверху | Один объект, фиксированный горизонт, известный объём признаков |
| Время укладывается в бюджет ответа | Измерено, а не предположено |
| Модель уже загружена | Загрузка артефакта не входит в обработку запроса |
| Отказ модели не ломает ответ | Прогноз необязателен, его отсутствие отображается явно |

Нарушение любого условия переводит операцию в фон.

### Контракт порта

`ForecastPort` объявляет обе формы, и бизнес-сервис выбирает подходящую:

```
ForecastPort
  .predict(series, horizon, context) -> ForecastResult          # прямой вызов
  .predict_batch(requests, context) -> BatchHandle              # постановка в фон
  .explain(prediction_id) -> FeatureContribution[]              # прямой вызов
  .explain_deep(prediction_id) -> ExplanationHandle             # постановка в фон
  .active_model(target) -> ModelVersion
```

Формы, возвращающие результат немедленно, и формы, возвращающие описатель фоновой операции, разделены явно. Метод не меняет способ выполнения скрыто: вызывающая сторона всегда знает, получит она результат или идентификатор операции.

### Обязательные ограничения синхронного пути

| Ограничение | Реализация |
|---|---|
| Жёсткий предел времени | Превышение прерывает вызов, а не удерживает запрос |
| Мягкая деградация | Недоступность модели даёт ответ без прогноза с указанием причины |
| Отдельный лимит частоты | Синхронный инференс не должен вытеснять обычные запросы |
| Наблюдаемость | Время инференса измеряется отдельно от общего времени ответа |

Первые два пункта существеннее прочих: синхронный инференс не должен превращать отказ модели в отказ всего эндпоинта. Прогноз — дополнение к карточке организации, а не условие её отображения.

### Требования контракта результата не меняются

Независимо от способа выполнения результат содержит версию модели, горизонт, ошибку модели и baseline, период входных данных, допущения и признак валидности. Синхронность — способ доставки, а не основание сократить состав ответа.

## Последствия

Становится проще: интерфейс отображает единичный прогноз без опроса состояния там, где это оправдано измерением. Способ выполнения становится решением, принимаемым по данным, а не догмой.

Становится сложнее: появляются два пути вместо одного, и оба нужно покрывать тестами. Требуется измерять время инференса, чтобы решение оставалось обоснованным.

Чем платим: риском, что синхронный путь будет применён там, где не следует. Компенсация — явное разделение методов порта и жёсткий предел времени.

## Пересмотр

Если измерения покажут, что единичный инференс не укладывается в бюджет ответа для реальной модели и реального объёма признаков, синхронный путь отключается переводом соответствующих вызовов на пакетную форму. Изменение локально: контракт порта уже содержит обе формы.
