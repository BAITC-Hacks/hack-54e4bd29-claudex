# ADR-0016. Экспериментальный краткосрочный прогноз потока направлений

**Статус:** Принят, частично заменяет [ADR-0014](0014-forecast-target-deferred-after-audit.md)  
**Дата:** PHASE 5A

## Контекст

ADR-0014 обоснованно запретил считать три месяца истории достаточными для
годовой сезонности и подтверждённого прогноза перегрузки. Последующая загрузка
подтвердила 767 130 направлений и непрерывный ежедневный ряд за
2025-01-01—2025-03-31. В `fact_referral_events` нет надёжного канонического
региона, а сопоставление организаций остаётся неполным. Поэтому уровень
`region × day` нельзя получить без выдуманного join.

Проекту нужен проверяемый ML-контур до получения длинной истории: построение
набора, временная валидация, сравнение с baseline, регистрация и хранение
происхождения результата. Такой контур можно проверить на глобальном
ежедневном потоке, если не переносить его метрики на другие сезоны и не
называть результат прогнозом перегрузки.

## Решение

Разрешён экспериментальный прогноз цели `DAILY_REFERRAL_COUNT`:

- область — `GLOBAL`; региональный и больничный прогнозы не публикуются;
- частота — день, горизонт — семь дней;
- история — агрегат `count()` по `registration_dt` из
  `fact_referral_events`;
- валидация — расширяющееся walk-forward окно с одинаковыми folds для всех
  кандидатов;
- обязательные baseline — последнее значение, значение семь дней назад и
  среднее последних семи дней;
- единственный ML-кандидат — `HistGradientBoostingRegressor` с лаговыми,
  скользящими и weekday-признаками;
- ML выбирается только если одновременно улучшает общие MAE и WAPE
  сильнейшего baseline минимум на 2 % и не ухудшает эти метрики ни на одном
  сопоставимом fold. При равенстве, нестабильности или неопределённой WAPE
  выбирается baseline;
- выбранный кандидат и метрики регистрируются в MLflow; прогноз и provenance
  добавляются в PostgreSQL без изменения прошлых запусков;
- чтение глобального результата разрешено только контексту с global scope;
- результат после окончания собственного горизонта помечается `STALE`.

Метрики описывают только walk-forward проверку внутри доступного квартала.
Они не подтверждают годовую устойчивость и не являются доказательством
точности в промышленной эксплуатации.

## Последствия

Появляется воспроизводимый ML-контур и честный baseline-first механизм выбора.
Baseline считается полноценным выбранным кандидатом, если ML не даёт
материального выигрыша. API и UI показывают горизонт, версию, watermark,
ошибку и ограничения, не создавая искусственного confidence.

Цена решения — один глобальный ряд не подходит для разграниченного
операционного прогноза регионов и организаций. Пользователи без global scope
получают 404, пока каноническая региональная или организационная связь не
подтверждена.

## Сохранённые запреты ADR-0014

- годовая и долгосрочная сезонность остаются неподтверждёнными;
- прогноз перегрузки, коек, пациента или очереди не строится;
- метрики квартального эксперимента не выдаются за production SLA;
- организациям и регионам не назначаются связи через fuzzy matching;
- устаревший результат не отображается как текущий.

## Пересмотр

Решение пересматривается после получения как минимум 24 месяцев истории,
официального справочника регионов/организаций или изменения источника и
семантики `registration_dt`. Переход к региональному уровню требует отдельной
валидации data scope и покрытия mapping.
