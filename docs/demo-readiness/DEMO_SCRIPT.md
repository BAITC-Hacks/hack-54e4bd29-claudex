# MedSignal demo script — 4–5 минут

Этот маршрут допустим только после закрытия P0 из `BLOCKERS.md` и нового PASS на точном SHA показа. Текущая проверка `78ff9ff...` не дала live browser PASS.

## Перед началом

- На экране открыт новый synthetic-only project; manifest SHA совпадает с демонстрируемым checkout.
- Backend `/ready` отвечает 200, а Playwright demo-readiness завершён без skipped.
- Используется свежий выделенный `NEW` synthetic signal. Не использовать карточку, которую уже менял тест или другой участник.
- Copilot выключен; API key и интернет для LLM не требуются.

## 0:00–0:35 — вход

1. Открыть `/signals` без сессии.
2. Показать экран входа и отсутствие защищённых данных.
3. Нажать `Войти через Keycloak`, войти test identity и дождаться возврата в приложение.

Сказать: «Это отдельный синтетический контур. Аутентификация проходит через локальный тестовый Keycloak; скрытие интерфейса не заменяет серверную проверку доступа».

Подтверждение на экране: после callback появляется `Лента предупреждений`; до входа таблицы сигналов нет.

## 0:35–1:45 — аналитика

1. Открыть `Аналитика`.
2. Показать период в форме и изменить группировку на недельную.
3. Показать historical/freshness labels и различие `—`, нулевых и suppressed значений, если они присутствуют в текущем manifest.
4. Если forecast отсутствует, показать ровно текст `Прогноз пока недоступен...`; не подставлять число. Если forecast интегрирован первым агентом, использовать только повторно проверенные даты, единицы и MAE.

Сказать: «Период и группировка входят в запрос backend. Это исторические синтетические данные, а не текущая загрузка коек».

Подтверждение на экране: изменённый период, ответ analytics и явное состояние forecast. MAE — ошибка прогноза, не процент точности.

## 1:45–2:40 — регион и организация

1. Открыть `Карта`, выбрать один доступный synthetic region.
2. Показать `Выбран регион` и обновившиеся backend-показатели.
3. Открыть организацию из таблицы.
4. Вернуться и открыть другую организацию; убедиться, что заголовок и показатели первой не остались.

Сказать: «Регион и организация ограничивают backend query. Несопоставленное, неизвестное и нулевое значение не объединяются».

Подтверждение на экране: имя выбранного региона, имя организации, период и source/mapping labels.

## 2:40–3:45 — сигнал и действие сотрудника

1. Открыть `Сигналы`, выбрать выделенный `NEW` signal с source `SYNTHETIC_DEV_SEED`.
2. Показать `Основание сигнала`, периоды, фактическое и базовое значения, исходное `Объяснение`.
3. Ввести нейтральную synthetic-причину и один раз нажать `Принять в работу`.
4. Обновить страницу, повторно пройти SSO-сессию и показать сохранённый статус/причину.

Сказать: «Правило обнаружило измеримое изменение; решение принимает сотрудник. Optimistic version не позволяет второй устаревшей карточке повторить действие».

Подтверждение на экране: `Закрыть как обработанный` вместо `Принять в работу`, сохранённая причина и audit/history.

## 3:45–4:30 — Copilot disabled

1. На той же карточке нажать `Объяснить сигнал`.
2. Показать `Функция отключена`.
3. Закрыть и снова открыть панель; убедиться, что нового запроса нет.
4. Показать, что исходный блок `Объяснение` остался на странице.

Сказать: «В этом QA-контуре Copilot намеренно выключен. Карточка и алгоритмическое объяснение работают без LLM; fixture-success не выдаётся за настоящий ответ модели».

Подтверждение на экране: `COPILOT_DISABLED` UI и неизменённое исходное объяснение.

## 4:30–5:00 — честное завершение

Сказать: «Показ относится только к указанному synthetic manifest и SHA. Это не production readiness, не диагноз, не оценка свободных коек и не официальная интеграция с министерством. После объединения forecast/design маршрут проверяется заново».
