# Семантика ожидания

## Возраст очереди в подтверждённом снимке

`fact_waiting_events` содержит предоставленный export/snapshot. `registration_dt`
— дата регистрации записи, а `snapshot_dt` — кандидат на дату среза, который
становится подтверждённым только после проверки поставки. Тогда допустима формула:

```text
queue_age_days = snapshot_dt - registration_dt
```

Сервер выбирает максимальный `snapshot_dt` только среди опубликованных импортов
поставки `WAITING`, для которой владелец явно подтвердил режим `SNAPSHOT` и
дату снимка, а проверка публикации сверила эту дату с аналитическими фактами.
Выбор ограничен областью доступа и фильтром идентичности организации.
Фильтры периода регистрации и профиля применяются **после выбора снимка**:
пустая когорта в новом снимке не заставляет сервер вернуться к старому.
Summary, overview, список и карточка организации берут записи **только этого
снимка**; старые снимки не суммируются.
Несколько частей одной подтверждённой поставки могут входить в один снимок.

`snapshot_at` — фактический `snapshot_dt` выбранного и подтверждённого снимка.
Текущий ingest заполняет `snapshot_dt` из `sdu_load_date`; это поле можно
трактовать как дату снимка **только после явного подтверждения владельца
поставки**, что оно обозначает момент среза, и проверки совпадения с manifest.
Если такого снимка нет, поле равно `null`, а
`snapshot_semantics_confirmed=false`. Время импорта и `source_load_date` не
служат заменой даты снимка. Если семантика поставки не подтверждена, количество
ожидающих и возраст очереди возвращаются как `null` (не как ноль); если поставка
подтверждена, но после фильтров нет строк, количество равно 0, а
`snapshot_at` сохраняет дату выбранного снимка. Если в разрешённой области
снимка нет вообще, `snapshot_at=null`. Фронтенд не выбирает снимок и не
рассчитывает его дату.

Диапазон `registration_dt` задаёт когорту записей внутри выбранного снимка,
а не период динамики очереди. Выбранный снимок может быть историческим;
`snapshot_semantics_confirmed` подтверждает смысл поставки, но не её
актуальность на сегодня. При отсутствии отдельного соглашения о частоте
поставки актуальность остаётся `UNKNOWN`. Часовой пояс исходного `DateTime64`
отдельно не подтверждён; API не добавляет UTC к времени без подтверждения.

## Наблюдаемое время ожидания

Для завершённого направления с корректной хронологией:

```text
observed_waiting_days = hospitalization_dt - registration_dt
```

Строки без госпитализации не входят в показатель. Строки с `hospitalization_dt < registration_dt` исключаются и показываются отдельным счётчиком качества. На текущих данных исключено 104 644 строки. Значение описывает историю завершённых случаев и не является прогнозом индивидуальной даты.

## Статус направления

1. `REFUSED`: корректная `refusal_dt` присутствует и имеет приоритет.
2. `HOSPITALIZED`: корректная `hospitalization_dt` присутствует, отказ отсутствует.
3. `WAITING`: обе даты исхода отсутствуют.
4. `UNKNOWN`: хронология исхода противоречит регистрации.

Это техническая классификация состояния записи, не клиническая интерпретация.
