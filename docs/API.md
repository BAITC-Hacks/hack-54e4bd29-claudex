# API — контракты REST API

> **Статус.** Контракты предварительные. Окончательная структура фиксируется после уточнения доменной модели и Data Audit. Источником истины во время разработки является OpenAPI-схема, генерируемая FastAPI по адресу `/api/v1/docs`.

## 1. Общие соглашения

| Аспект | Решение |
|---|---|
| Базовый путь | `/api/v1` |
| Формат | JSON, UTF-8 |
| Именование полей | `snake_case` |
| Время | ISO 8601 с часовым поясом, хранение в UTC |
| Версионирование | В пути. Несовместимые изменения — новая версия |
| Аутентификация | `Authorization: Bearer <token>` |
| Идентификатор запроса | Заголовок `X-Request-ID` принимается и возвращается |
| Тяжёлые операции | Возвращают `202 Accepted` и идентификатор задачи |

### 1.1 Пагинация

Списочные ответы всегда постраничные. Неограниченная выдача не поддерживается ни на одном эндпоинте.

```json
{
  "items": [],
  "page": 1,
  "page_size": 50,
  "total": 0,
  "has_next": false
}
```

Параметры: `page`, `page_size` с жёстким верхним пределом. Запрос сверх предела отклоняется, а не молча усекается.

### 1.2 Формат ошибки

```json
{
  "error": {
    "code": "FORECAST_NOT_AVAILABLE",
    "message": "Прогноз не построен: недостаточно истории наблюдений",
    "details": {"required_days": 180, "available_days": 42},
    "request_id": "0f9c1b2e-..."
  }
}
```

Сообщение об ошибке не раскрывает внутреннее устройство системы: ни SQL, ни трассировку, ни имена таблиц. Подробности остаются в логе, связанном по `request_id`.

### 1.3 Коды ответов

| Код | Применение |
|---|---|
| 200 | Успешное чтение |
| 201 | Ресурс создан |
| 202 | Задача принята в обработку |
| 400 | Некорректный запрос |
| 401 | Не аутентифицирован |
| 403 | Нет прав или объект вне области данных |
| 404 | Ресурс не найден |
| 409 | Конфликт состояния, например недопустимый переход статуса |
| 422 | Ошибка валидации тела запроса |
| 429 | Превышен лимит частоты запросов |
| 500 | Внутренняя ошибка |

Решение по `403` и `404`: для объекта вне области данных пользователя возвращается `404`, а не `403`. Ответ `403` подтверждает существование объекта и позволяет перебором выяснить состав организаций.

## 3. Аутентификация

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/v1/auth/login` | Вход (режим `local`) |
| POST | `/api/v1/auth/refresh` | Обновление токена |
| POST | `/api/v1/auth/logout` | Завершение сессии |
| GET | `/api/v1/auth/me` | Текущий пользователь, роль, область данных |

В режиме `oidc` вход выполняется через внешнего провайдера, а `/auth/me` остаётся единой точкой получения контекста для frontend.

## 5. Медицинские организации

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/hospitals` | Список с фильтрами `region_id`, `risk_level`, `has_active_signals`, сортировкой и пагинацией |
| GET | `/api/v1/hospitals/{id}` | Карточка организации с профилем и текущим риском |
| GET | `/api/v1/hospitals/{id}/metrics` | Временные ряды показателей |
| GET | `/api/v1/hospitals/{id}/forecast` | Актуальный прогноз |
| GET | `/api/v1/hospitals/{id}/signals` | Сигналы по организации |

### 5.1 Параметры запроса метрик

`metric_codes`, `date_from`, `date_to`, `granularity` (`day`, `week`, `month`), `normalized` (`true` или `false`).

Фильтрация и агрегация выполняются на сервере. Диапазон дат ограничен максимальной длиной окна; при превышении запрос отклоняется с указанием предела. Frontend получает агрегированный ряд, а не сырые наблюдения.

### 5.2 Ответ прогноза

```json
{
  "hospital_id": "...",
  "target": "incoming_flow",
  "horizon_days": 14,
  "points": [{"date": "2026-09-25", "value": 118.0, "lower": 96.0, "upper": 140.0}],
  "model_version": "lgbm-incoming-flow@7",
  "error_metric": {"name": "WAPE", "value": 0.112},
  "baseline_error_metric": {"name": "WAPE", "value": 0.147, "baseline": "seasonal_naive"},
  "is_valid": true,
  "invalidity_reason": null,
  "generated_at": "2026-09-11T03:15:00Z",
  "input_period": {"from": "2026-03-01", "to": "2026-09-10"},
  "assumptions": [
    "Сохраняется действующий порядок маршрутизации направлений",
    "Модель не учитывает изменения плановой мощности организации"
  ],
  "disclaimer": "Расчётный прогноз. Решение принимает уполномоченный сотрудник."
}
```

Поле `disclaimer` приходит с сервера. Дисклеймер относится к смыслу данных и не должен зависеть от того, не забыл ли его добавить фронтенд.

## 6. Сигналы

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/signals` | Лента предупреждений с фильтрами |
| GET | `/api/v1/signals/{id}` | Карточка ситуации |
| PATCH | `/api/v1/signals/{id}/status` | Смена статуса |
| POST | `/api/v1/signals/{id}/assign` | Назначение ответственного |
| GET | `/api/v1/signals/{id}/history` | История изменений сигнала |

Фильтры ленты: `status`, `severity`, `signal_type`, `region_id`, `hospital_id`, `detected_from`, `detected_to`, `assigned_to_me`.

### 6.1 Карточка сигнала

Ответ объединяет всё, что нужно для решения: severity, организация, тип, момент обнаружения, значения метрик с периодом сравнения, связанный прогноз, объяснение с факторами, качество модели, качество данных, статус, ответственный, доступные переходы, ссылки на сценарии и история аудита.

Поле `available_transitions` вычисляется сервером с учётом роли. Frontend не решает, какие переходы разрешены.

### 6.2 Смена статуса

```json
{ "status": "IN_PROGRESS", "assignee_id": "...", "comment": "Взято в работу" }
```

Правила: переход в `IN_PROGRESS` требует ответственного, переход в `CLOSED` требует причины, недопустимый переход даёт `409`, любой успешный переход порождает запись аудита.

## 9. Симуляции

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/v1/simulations` | Запуск расчёта сценария, `202 Accepted` |
| GET | `/api/v1/simulations/{id}` | Статус и результат |
| GET | `/api/v1/simulations` | История сценариев пользователя |

### 9.1 Запрос

```json
{
  "scenario_type": "INCOMING_FLOW_CHANGE",
  "hospital_id": "...",
  "parameters": {"flow_change_pct": -15},
  "horizon_days": 14,
  "signal_id": "..."
}
```

Для переноса потока — `scenario_type: "FLOW_REDISTRIBUTION"` с полями `source_hospital_id`, `target_hospital_id` и `share_pct`. Запрос отклоняется с `400`, если организации несопоставимы, с указанием причины.

### 9.2 Ответ

Содержит базовый прогноз и расчётный сценарий, а при переносе — обе организации отдельно. Обязательные поля: `assumptions`, `limitations`, `result_label` со значением «Расчётный сценарий» и `disclaimer`. Формулировка «рекомендация» в контракте отсутствует.

## 10. Действия и аудит

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/actions` | Действия по сигналу или пользователю |
| POST | `/api/v1/actions` | Фиксация принятого решения |
| GET | `/api/v1/audit` | Журнал аудита с фильтрами и пагинацией |

Журнал доступен только ролям с соответствующим правом и всегда ограничен областью данных. Записи не изменяются и не удаляются — методов `PATCH` и `DELETE` не существует.

## 11. Импорт данных

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/v1/data/import` | Загрузка выгрузки, `202 Accepted` |
| GET | `/api/v1/data/imports` | Список импортов |
| GET | `/api/v1/data/imports/{id}` | Статус и статистика |
| GET | `/api/v1/data/imports/{id}/quality-report` | Отчёт о качестве данных |
| GET | `/api/v1/data/quality` | Текущее состояние качества по организациям |

Ограничения: размер файла ограничен на уровне Nginx и приложения, тип файла проверяется по содержимому, а не по расширению, эндпоинт имеет отдельный жёсткий лимит частоты. Загруженный файл не исполняется и не разбирается синхронно.

## 12. Администрирование

| Метод | Путь | Назначение |
|---|---|---|
| GET / POST | `/api/v1/admin/users` | Пользователи |
| PATCH | `/api/v1/admin/users/{id}` | Изменение пользователя, роли, области данных |
| GET | `/api/v1/admin/roles` | Роли и права |
| GET / PATCH | `/api/v1/admin/config` | Конфигурация правил, весов и порогов |

Изменение конфигурации правил и весов версионируется и попадает в аудит: оно меняет поведение системы и смысл ранее рассчитанных оценок.

## 13. Ограничения частоты запросов

| Категория | Ограничение |
|---|---|
| Неаутентифицированные запросы | `RATE_LIMIT_ANONYMOUS_PER_MIN` |
| Аутентифицированные запросы | `RATE_LIMIT_AUTHENTICATED_PER_MIN` |
| Импорт, симуляции, экспорт | `RATE_LIMIT_HEAVY_ENDPOINTS_PER_MIN` |

При превышении возвращается `429` с заголовком `Retry-After`.

## 14. Правила проектирования эндпоинтов

| Правило | Обоснование |
|---|---|
| Контроллер не содержит бизнес-логики | Логика в business-сервисе |
| Ответ описан Pydantic-схемой | Исключает утечку внутренних полей |
| Вход валидируется независимо от frontend | Клиент не является доверенной стороной |
| Область данных применяется всегда | Отсутствие фильтра — ошибка, а не значение по умолчанию |
| Списки всегда постраничные | Защита от неограниченной выдачи |
| Тяжёлые операции асинхронны | Соблюдение бюджета HTTP-запроса |
| Дисклеймеры приходят с сервера | Смысл данных не зависит от клиента |
