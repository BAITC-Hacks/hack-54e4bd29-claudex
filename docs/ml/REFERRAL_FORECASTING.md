# Краткосрочный прогноз потока направлений

## Назначение и границы

PHASE 5A прогнозирует только число зарегистрированных направлений на
плановую госпитализацию по дням. Цель — `DAILY_REFERRAL_COUNT`, горизонт —
семь календарных дней. Это экспериментальный расчёт потока, а не прогноз
перегрузки, наличия коек, состояния пациента или даты госпитализации.

Уровень прогноза — глобальный. В подтверждённой схеме
`fact_referral_events` нет надёжного канонического региона, а 42 региональных
представления и часть организаций не сопоставлены. Поэтому `region × day`
потребовал бы неподтверждённого join. До официального mapping региональные и
больничные прогнозы не публикуются.

## Источник и воспроизводимость

Авторитетный запрос считает строки `fact_referral_events` по
`toDate(registration_dt)`, сортирует дни и ограничивает чтение 400 точками.
Событийные записи не передаются в ML-пакет. Dataset watermark содержит IDs,
SHA-256 и время завершения всех опубликованных импортов `REFERRALS`.

Построитель формирует плотный ежедневный ряд. Отсутствующая календарная дата
заполняется нулевым count и записывается в `missing_dates`; это делает
преобразование явным и воспроизводимым. Метаданные включают диапазон, число
дней, область, watermark и `feature_schema_version=referrals_daily_v1`.

## Признаки

Все признаки рассчитываются только из значений, предшествующих target date:

| Признак | Определение |
|---|---|
| `lag_1`, `lag_2`, `lag_3`, `lag_7` | Значение цели за 1, 2, 3 и 7 дней до даты |
| `rolling_mean_7` | Среднее семи закрытых предыдущих дней |
| `rolling_std_7` | Стандартное отклонение семи закрытых предыдущих дней |
| `day_of_week` | День недели target date, известный заранее |

Год, месяц, праздники и годовая сезонность не используются. Рекурсивный
семидневный прогноз добавляет предыдущее предсказание в рабочую историю;
фактические значения будущего fold туда не попадают.

## Кандидаты и валидация

Три baseline являются полноценными моделями:

1. `naive_last` — последнее наблюдение;
2. `weekly_naive` — значение семь дней назад;
3. `moving_average_7` — среднее последних семи дней.

Один ML-кандидат — `HistGradientBoostingRegressor` из scikit-learn. Он выбран
как компактная табличная модель без нового forecasting framework. Параметры
детерминированы; несколько ML-семейств в этой фазе не сравниваются.

Валидация использует expanding-window rolling origin. Минимальное окно по
умолчанию — 42 дня, validation horizon и шаг — семь дней. Все кандидаты
получают одинаковые folds. На каждом fold обучение заканчивается раньше
первой даты validation.

## Метрики и выбор

Для каждого fold и объединённой выборки рассчитываются MAE, WAPE и RMSE.
Если сумма абсолютных фактических значений равна нулю, WAPE возвращается как
`null`, а не заменяется нулём или бесконечностью.

Сначала выбирается baseline с наименьшими MAE, WAPE и RMSE. ML становится
выбранным кандидатом только если одновременно улучшает общие MAE и WAPE
минимум на `FORECAST_MIN_RELATIVE_IMPROVEMENT` (по умолчанию 2 %) и не
ухудшает MAE/WAPE baseline ни на одном сопоставимом fold. При равенстве,
нестабильности или неопределённой WAPE остаётся baseline.

## Хранение и доступ

MLflow сохраняет параметры, общие и fold-метрики, evaluation JSON и
зарегистрированный артефакт выбранного кандидата. PostgreSQL добавляет
`model_versions`, `forecasts` и семь `forecast_points`. Новый запуск создаёт
новую версию; прошлый прогноз не обновляется.

Backend читает сохранённый прогноз через `ForecastQueryService`; HTTP route не
импортирует ML-библиотеки. Глобальный прогноз доступен только SecurityContext
с global scope. Ограниченные региональные и больничные контексты получают
404, чтобы не перечислять глобальные результаты.

Если `forecast_end` уже в прошлом, API возвращает `freshness_status=STALE` и
явное ограничение. Здесь нет выдуманного SLA: завершение собственного периода
прогноза является объективным критерием.

## Запуск

```bash
docker compose up -d --build
docker compose run --rm ml-runner
```

Эквивалентная команда Make:

```bash
make ml-build
make ml-train-referrals
```

Тесты и воспроизведение оценки:

```bash
make test-ml
```

API после успешного запуска:

```text
GET /api/v1/forecasts/referrals/latest
```

Ответ содержит историю агрегатов, прогноз, baseline, delta, версию модели,
метрики, watermark, даты, freshness и обязательный disclaimer.

## Условия расширения

Региональный/организационный уровень разрешается только после официального
mapping и проверки data scope. Сезонные модели требуют минимум 24 месяцев
сопоставимой истории. Прогноз перегрузки требует наблюдаемой метки или
обоснованного operational proxy и данных о мощности/коечном фонде.
