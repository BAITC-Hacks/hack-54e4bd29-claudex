# Copilot: проверяемый синтетический показ

Copilot v1 объясняет выбранный синтетический сигнал. Он не является свободным чатом, медицинской рекомендацией, прогнозом даты выписки или сведением о наличии коек. Алгоритмическое объяснение сигнала остаётся на странице независимо от Copilot.

## Код и окружение

- Рабочая ветка: `feature/copilot-signal-explanation`.
- Исходный HEAD перед сохранением backend-исправлений: `e821c87ba32101ce690d04bd4c6a74ac43837d0a`.
- Проверенный backend HEAD перед UI-изменениями: `d68492b7c2dbad08a4098d0c435c5befaacd6f87`.
- HEAD коммита с UI: `4b4b996183a754ac905e00efc78052a8fa455eae`.
- Фактический HEAD проверяемой копии всегда определяйте командой `git rev-parse HEAD`; после browser/demo-коммита он отличается от UI HEAD. Не переключайтесь на старый `main` для этого показа.
- Используйте только изолированный synthetic acceptance Compose project с loopback origin и его сгенерированным тестовым Keycloak realm. Не подменяйте его реальными медицинскими данными.

На Windows PowerShell из корня текущей рабочей ветки соберите и запустите frontend с публичным issuer именно synthetic acceptance:

```powershell
$env:NEXT_PUBLIC_APP_ENV = 'local'
$env:NEXT_PUBLIC_OIDC_ISSUER = 'http://127.0.0.1:59583/auth/realms/medsignal'
$env:NEXT_PUBLIC_API_BASE_URL = '/api/v1'
cd frontend
npm ci
npm run build
npm run start -- -p 43111 -H 127.0.0.1
```

Порт `43111` здесь локальный frontend для тестового browser proxy; Keycloak redirect остаётся на разрешённом acceptance origin `127.0.0.1:59583`. Перед browser-тестом установите `MEDSIGNAL_E2E_BASE_URL` на этот origin, `MEDSIGNAL_E2E_REALM` на локальный игнорируемый `realm.json`, `MEDSIGNAL_COPILOT_FRONTEND_URL` на `http://127.0.0.1:43111`. Запустите `npm run test:e2e -- e2e/copilot.spec.ts`. Не публикуйте realm, cookies, токены или ключ. Browser proxy подставляет только текущий UI; API и OIDC обслуживаются synthetic acceptance. При редиректе Keycloak тест один раз перезагружает callback-документ, чтобы он использовал ту же сборку UI и сохранил PKCE state в текущей вкладке.

Тест успешной панели использует **только synthetic fixture** ответа Copilot. Настоящий OIDC и backend предоставляют список и карточку сигнала. Второй browser-тест проверяет настоящий ответ `COPILOT_DISABLED` от текущего backend-кода при `COPILOT_ENABLED=false`: он требует временно смонтировать текущий каталог `backend` read-only в backend-контейнер изолированного acceptance project через игнорируемый локальный Compose overlay. После теста восстановите исходный backend командой `./scripts/copilot/launch-synthetic.ps1 -AcceptanceDir <absolute-synthetic-acceptance-dir> -Restore`. Ни base/production Compose, ни Keycloak, ни MinIO, ни volumes не меняются.

Отдельный платный browser smoke включается только явным `MEDSIGNAL_COPILOT_LIVE=1` и запуском `npm run test:e2e -- e2e/copilot.spec.ts --grep 'paid browser'`. До этого владелец должен отдельно разрешить **один** вызов и локально запустить согласованный `scripts/copilot/launch-synthetic.ps1` со скрытым вводом ключа; ключ не передаётся frontend. Тест выполняет один POST без retry и сохраняет только HTTP status, latency, provider/model, request_id и булевы результаты проверок. Usage токенов browser API не возвращает; при необходимости оно извлекается отдельно из ограниченных структурированных backend log fields без сохранения текста ответа. Без `MEDSIGNAL_COPILOT_LIVE=1` этот тест не входит в CI/обычный browser run.

## Шаги сотрудника

1. Войти тестовой учётной записью через Keycloak и открыть `/signals`.
2. Выбрать существующий сигнал типа «рост очереди», у которого сервер показывает `SYNTHETIC_DEV_SEED` и подтверждённое синтетическое происхождение. UUID из `API_V1.md` — пример, не live ID.
3. Открыть карточку `/signals/{id}`. Убедиться, что исходное алгоритмическое объяснение видно до нажатия.
4. Нажать «Объяснить сигнал» **один раз**. Если Copilot выключен, увидеть «Функция отключена»; основная карточка продолжает работать. Если специально включён согласованный синтетический backend с ключом, дождаться ответа без повторных нажатий.
5. В правой панели проверить качественный текст, блок «На каких данных основано», значения и единицы из backend facts, периоды и ограничения. `21` с единицей `percent_change` означает процентное изменение, а не количество пациентов. `null` отображается как «Неизвестно». Время генерации отдельно от периода исходных данных.
6. Раскрыть «Сведения о формировании» для provider, model, времени генерации и `request_id`. Не трактовать дату загрузки как дату снимка очереди.
7. Закрыть панель по Escape или кнопке; фокус возвращается на «Объяснить сигнал». Повторное открытие не делает новый платный запрос.
8. Перейти к сигналу другой синтетической организации. Прежний ответ не должен появиться и новый запрос не должен запускаться без нового нажатия.

При отсутствии ключа или отказе провайдера панель показывает конкретное безопасное состояние и не выдумывает «AI-ответ». Для `COPILOT_PROVIDER_UNAVAILABLE` и `COPILOT_PROVIDER_TIMEOUT` доступно только ручное повторение. `COPILOT_INVALID_RESPONSE` не раскрывает непроверенный текст. `429` показывает `Retry-After`, только если сервер прислал заголовок. Ни одно состояние не выполняет автоматическую повторную платную генерацию.

## Уровни доказательств

| Уровень | Что подтверждается | Текущий статус |
| --- | --- | --- |
| A | Component/API-client tests: состояния, контракт, один запрос, очистка контекста, безопасный текст | PASS после локального regression |
| B | Browser: реальный тестовый OIDC, существующий синтетический Signal, текущий backend с `COPILOT_DISABLED`; UI fixture отдельно | PASS для неплатного пути |
| C | Browser → текущий backend → настоящий OpenAI Responses API → UI | PASS: один отдельно разрешённый synthetic smoke, без retry |

В UI-цикле один платный browser POST вернул HTTP 200 за 3 223 мс, `request_id=4265d4481dd7167e6b6aa19336df8b7e`, provider `openai`, model `gpt-4.1-mini-2025-04-14`. Проверены схема ответа, существование `fact_ids`, соответствие выбранному сигналу, синтетическое ограничение, `data_current=false`, отсутствие числового утверждения в свободном тексте и отображение ответа в панели. Browser выполнил ровно один POST; backend восстановлен без ключа. Usage токенов не является частью browser API и в этом UI smoke не зафиксировано. Безопасная машинная метаинформация лежит только в игнорируемом `tmp/copilot-demo/live-browser-metadata.json`.

Три предыдущих HTTP 200 относятся к [отдельному backend smoke](LIVE_VERIFICATION_RESULT.md). Полные prompts/responses не сохраняются. Скриншоты только synthetic fixture находятся в игнорируемом `tmp/copilot-demo/screenshots/` и не должны коммититься. Успех одного browser smoke не доказывает надёжность на всех сигналах и не разрешает отправку реальных медицинских данных.

## Прогноз по кейсу 1

В текущем коде есть `GET /api/v1/forecasts/referrals/latest` и карточка `ReferralForecastCard` на `/dashboard`: она показывает сохранённый прогноз входящего потока, baseline, версию модели, горизонт, freshness и **MAE из сохранённого ответа**. Экран `/monitor/model` также открывает данные прогноза. Это не прогноз конкретной свободной койки или даты выписки. Наличие актуального forecast в конкретной demo-базе и его численное MAE перед показом проверяется отдельно; никаких значений точности этот документ не предполагает.
