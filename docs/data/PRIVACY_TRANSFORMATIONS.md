# MedSignal — преобразования приватности

## 1. Где проходит граница

```
файл источника          код случая, номер пациента, наименование диагноза
   ↓
разбор и проверки       значения ещё исходные
   ↓
═══ ГРАНИЦА ═══         псевдонимизация и отбор столбцов
   ↓
аналитическое хранилище только псевдонимы и коды
```

Граница проходит до записи, а не после. Загрузить сырой идентификатор
и обезличить его потом означает, что он какое-то время лежал в
хранилище, а «какое-то время» при первом же сбое превращается
в «навсегда».

## 2. Псевдонимизация

Применяется HMAC-SHA256 с секретом `DATA_PSEUDONYMIZATION_KEY`.

Обычный SHA-256 здесь не годится. Код случая имеет предсказуемую
структуру «регион.организация.профиль.номер», и пространство значений
мало: хеш такого значения подбирается перебором за минуты. Секрет делает
перебор бесполезным для того, у кого секрета нет.

| Набор | Что псевдонимизируется | Столбец витрины |
|---|---|---|
| REFERRALS | `hospitalization_code` | `event_key` |
| WAITING | регион + организация + профиль + номер пациента | `patient_key` |

Псевдоним очереди строится по составному значению, а не по номеру
пациента: номер имеет всего 8 680 различных значений на 765 182 записи
и сам по себе склеил бы разных людей в одного.

Свойства:

- **Детерминирован.** Одно значение при одном секрете даёт один результат,
  иначе записи одного случая нельзя было бы связать между поставками.
- **Нормализован до хеширования.** Регистр и пробелы не создают второго
  псевдонима у того же случая.
- **Части разделены символом, не встречающимся в данных.** Простая склейка
  позволила бы разным наборам частей дать одну строку.

### Требования к секрету

- Только переменная окружения. В Git не попадает.
- Не короче 32 символов. Проверяется при старте приложения и при создании
  конвейера — оба пути ведут к записи данных.
- Значение из `.env.example` вне локальной среды отвергается: приложение
  не стартует.
- Не выводится ни в журнал, ни в исключение, ни в отчёт. Объект
  псевдонимизатора печатает `<секрет скрыт>`.

Смена секрета обрывает связуемость с прежними поставками. Это осознанная
цена: секрет меняют, когда считают скомпрометированным, и сохранять
связуемость с утёкшим ключом бессмысленно.

## 3. Столбцы, не попадающие в витрину

| Столбец | Набор | Почему |
|---|---|---|
| `hospitalization_code` | REFERRALS | Содержит номер пациента |
| `patient_seq_no` | WAITING | Номер пациента |
| `diagnosis_name` | REFERRALS, WAITING | Читаемый диагноз на уровне записи |
| `icd_name` | REFUSALS | То же |
| `operation_code`, `operation_name` | WAITING | Сведения о вмешательстве |

Вместо читаемого диагноза в витрине хранится код МКБ-10: для аналитики
его достаточно, а восстановить по коду обстоятельства конкретного
человека труднее.

Запрет выражен не только выбором столбцов при сборке записи, но и
проверкой: набор запрещённых столбцов объявлен в контракте, и попытка
перенести любой из них прерывает импорт. Проверка избыточна по
построению — она существует, чтобы будущая правка упала здесь, а не
обнаружилась в хранилище через полгода.

## 4. Что остаётся чувствительным

Псевдонимизация не делает данные безличными.

- Сочетание организации, даты и кода диагноза остаётся
  квазиидентификатором, особенно в редких сочетаниях.
- Социальные признаки в отказах — проживание, страхование, льготная
  категория — сужают круг лиц.
- Возраст в витринах не хранится вовсе.

Отсюда правило: события на уровне записи наружу не выдаются. Аналитика
работает с агрегатами, доступ к событиям ограничен правами.

## 5. Карантин

Отклонённые строки сохраняются в исходном виде — в этом смысл карантина:
владелец данных должен увидеть, что именно конвейер отказался принять.

Поэтому карантин лежит в зоне ограниченного доступа `medsignal-quarantine`,
не выдаётся аналитическим API и не индексируется витринами. В PostgreSQL
хранится только адрес объекта и коды причин.

## 6. Отчёт о качестве

Сообщения содержат счётчики и коды правил, но никогда — значения.

Верно: `17 строк содержат неразобранную дату регистрации`.

Неверно и невозможно: сообщение с кодом случая или диагнозом.

Отчёт читают люди без доступа к медицинским данным, и он не должен
становиться каналом утечки.
