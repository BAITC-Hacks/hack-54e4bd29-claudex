# MedSignal — правила проверки качества

## 1. Четыре уровня

Уровни различаются не строгостью, а тем, что каждый знает.

| Уровень | Знает | Примеры |
|---|---|---|
| 1. Файл | размер и формат, но не столбцы | пустой файл, нечитаемый файл |
| 2. Схема | состав столбцов, но не значения | отсутствующий столбец, лишний столбец, неразобранное значение |
| 3. Справочники | значения, но не бизнес-смысл | несопоставленная организация, регион, профиль |
| 4. Бизнес-правила | связи значений между собой | порядок дат, отрицательные счётчики, границы правдоподобия |

## 2. Исход строки

| Исход | Когда |
|---|---|
| `VALID` | замечаний нет |
| `VALID_WITH_WARNING` | замечание есть, смысл записи сохранён |
| `REJECTED` | включение строки исказило бы аналитику |

Отклонение — крайняя мера. Отсутствие необязательного поля строки
не стоит: выгрузка, у которой половина профилей коек пуста, всё равно
отвечает на вопрос «сколько направлений пришло в организацию».

## 3. Правила, отклоняющие строку

| Код | Смысл |
|---|---|
| `MISSING_REQUIRED_VALUE` | нет значения, без которого запись бессмысленна |
| `INVALID_REGISTRATION_DATE` | дата регистрации не разобрана |
| `INVALID_REFUSAL_DATE` | дата отказа не разобрана |
| `INVALID_SNAPSHOT_DATE` | дата среза не разобрана |
| `DATE_OUT_OF_RANGE` | дата вне правдоподобных границ |
| `NEGATIVE_AGGREGATE` | отрицательное значение в счётном поле |

Границы правдоподобия: не раньше 2015 года и не позже чем на пять лет
вперёд. Верхняя граница намеренно широка: плановая дата госпитализации
законно уходит в будущее, и обрезать её по «сегодня» было бы ошибкой.
Задача проверки — поймать испорченное значение вроде года 0001, а не
заменить собой суждение владельца данных.

## 4. Правила, дающие предупреждение

| Код | Смысл |
|---|---|
| `SCHEMA_UNPARSEABLE_VALUE` | значение было, но не разобралось |
| `HOSPITALIZATION_BEFORE_REGISTRATION` | госпитализация раньше регистрации |
| `REFUSAL_BEFORE_REGISTRATION` | отказ раньше регистрации |
| `UNMAPPED_ORGANIZATION` | организация не сопоставлена со справочником |
| `UNMAPPED_REGION` | регион не сопоставлен |
| `UNMAPPED_PROFILE` | профиль койки не сопоставлен |

Порядок дат подозрителен, но строка всё ещё описывает направление, и
терять её незачем. На реальной выгрузке правило срабатывает на 104 644
строках из 767 130 — это заметная доля, и её причину должен объяснить
владелец данных.

## 5. Правила-сведения

| Код | Смысл |
|---|---|
| `CONDITIONAL_NULL_EXPECTED` | пусто там, где пусто по смыслу |
| `AUDIT_ROW_COUNT_DRIFT` | число строк расходится с отчётом Data Audit |

Сверка с отчётом аудита выполняется по набору целиком, а не по файлу:
набор поставляется частями, и ожидаемое число строк относится ко всем
частям вместе.

## 6. Чего проверки не делают

- Не придумывают медицинских правил. Проверяется только то, что очевидно
  из смысла поля.
- Не исправляют значения.
- Не сопоставляют организации по похожести.
- Не отклоняют строку из-за неизвестной организации: официального
  справочника ещё нет, и такое отклонение оставило бы систему без данных.

## 7. Где хранится результат

| Что | Где |
|---|---|
| Замечания в агрегированном виде | PostgreSQL, `data_quality_results` |
| Отклонённые строки целиком | MinIO, `medsignal-quarantine` |
| Счётчики поставки | PostgreSQL, `data_imports` |

Строки на каждую отклонённую запись в PostgreSQL не пишутся: полтора
миллиона записей об ошибках сделали бы таблицу нечитаемой и заодно
перенесли бы в базу приложения те самые данные, ради защиты которых
существует карантин.

## 8. Инвариант учёта

После каждого пакета проверяется, что принятых и отклонённых строк вместе
столько же, сколько прочитано. Расхождение прерывает импорт.

Проверка появилась не из осторожности. Сравнение отсутствующего числа
с нулём даёт пустое значение, а не «ложь»; попав в маску отклонения, оно
выводило строку и из принятых, и из отклонённых. На выгрузке отказов так
терялась четверть записей — 368 272 строки, у которых не указана сумма.
Ошибка была найдена именно этой сверкой.
