# MedSignal

MedSignal помогает сотруднику здравоохранения увидеть поток направлений, проверить основания операционного сигнала и зафиксировать управленческое действие.

Команда **Claudex**. GovTech Camp, [кейс 1](docs/GOVTECH_TRACEABILITY.md), задача в сфере здравоохранения. Отдельное официальное название трека в документах репозитория не зафиксировано.

## Задача и пользователи

Направления, ожидание и отказы нужно сопоставлять по периоду, региону и организации, видеть происхождение показателя и выполненные действия.

Пользователи — сотрудники органов управления здравоохранением, региональные координаторы и уполномоченные сотрудники организаций. Рабочий процесс: «наблюдение → проверка фактов → действие → история».

## Что реализовано

В сдаваемом `main` присутствуют:

- Ситуационный центр: исторические KPI с единицами, периодом и областью доступа, динамика, организации, сигналы и прогноз.
- Аналитика направлений, ожидания и отказов; фильтры периода, региона и организации, сохранение контекста при переходе и возврате.
- Каталог организаций: поиск, фильтрация, сортировка, страницы результатов и детализация.
- Карта Казахстана: региональные показатели из защищённого API, а не подставные ответы браузера. Она не измеряет занятость коек.
- Семидневный прогноз направлений с историческими точками, метриками и версией модели.
- Сигналы: тип, статус, период, область, происхождение, сохранённые основания и алгоритмическое объяснение.
- Действия сотрудника, комментарии и история; переходы `NEW → IN_PROGRESS → CLOSED` с проверкой версии карточки.
- Вход через Keycloak/OIDC, серверные роли и ограничения области доступа; русский и казахский интерфейс.
- Необязательный Copilot и сохранённые расчётные сценарии изменения входящего потока. Сценарии не являются прогнозом доступности коек.

Основные каталоги: `frontend/` — интерфейс, `backend/` — API и workflow, `data_pipeline/` — публикация данных, `ml/` — прогноз. [Архитектура](docs/ARCHITECTURE.md) и [контракты API](docs/API.md) описаны отдельно.

## Как работает продукт

Вход → ситуационный центр → организация → прогноз → сигнал → проверка оснований → действие сотрудника.

Сотрудник изучает организацию и возвращается без потери фильтров, отдельно рассматривает прогноз, открывает сигнал и проверяет правило, показатели и источник. Числовые поля показываются только при наличии в основаниях. Прогноз не называется причиной сигнала без подтверждённой связи.

«Принять в работу» сохраняет действие; статус и история доступны после обновления страницы. Решение остаётся за сотрудником; Copilot не заменяет алгоритмическое объяснение.

## AI и прогноз

Проверяемый контракт: `DAILY_REFERRAL_COUNT`, область `GLOBAL`, горизонт **7 дней**, единица — **направлений/день**. Pipeline использует опубликованный исторический ряд, временные окна проверки и сравнение с baseline. Сложная модель не выбирается только ради демонстрации AI.

MAE — средняя абсолютная ошибка на исторической временной проверке, **не процент точности**. Интерфейс показывает MAE и baseline MAE, периоды проверки и прогноза, версию модели и historical/stale status.

В [эксперименте 27 сентября](docs/acceptance/FORECAST_DEMO_VERIFICATION.md) использованы 2 019 синтетических направлений за январь–март 2025 года: 90 дней, 6 временных окон, 42 пары проверки. Выбран `weekly_naive`; MAE и baseline MAE — **1,5714285714 направления/день**. Это результат указанного в отчёте набора и версии, не метрика любой текущей базы. Отдельного финального holdout в этом эксперименте нет.

Прогноз не оценивает свободные койки, даты выписки или очереди и не является медицинской рекомендацией. [Контракт прогнозирования](docs/ml/REFERRAL_FORECASTING.md).

Copilot дополнительно поясняет разрешённые факты сигнала. Backend проверяет доступ, источники и числовые утверждения ответа. Запрос выполняется по нажатию, не автоматически; при отключении доступно состояние «AI-пояснение временно недоступно». Ключ хранится на сервере. [Контракт Copilot](docs/copilot/API_V1.md).

## Как запустить и проверить

Поддерживаемый путь — новый изолированный локальный synthetic-проект. Нужны Python 3.12, работающий Docker Engine/Compose, Git и GnuPG; в Linux требуется `setfacl`. Команды из корня checkout, PowerShell. **При ошибке остановитесь, gates не обходите.**

```powershell
python -m pip install -r backend/requirements-dev.txt
python -m pip install -r ml/requirements.txt
$project = 'phase8-local-demo-' + [guid]::NewGuid().ToString('N').Substring(0, 8)
python -m scripts.operations.minio_source_build build --project $project --patched-acceptance
python -m scripts.operations.minio_advisory_gate --project $project
python -m scripts.operations.minio_source_scan --project $project
python -m scripts.operations.minio_cve_probe --project $project
python -m scripts.operations.prepare_acceptance prepare --project $project --minio-source-build
python -m scripts.operations.prepare_acceptance start --project $project
python -m scripts.local_demo.bootstrap --project $project
$projectDir = Join-Path (Get-Location).Path "tmp/acceptance/$project"
$compose = @('--project-name', $project, '--env-file', "$projectDir/.env", '--file', 'docker-compose.yml', '--file', "$projectDir/compose.override.yml")
docker compose @compose --profile tools run --rm ml-runner
python -m scripts.local_demo.verify --project-dir $projectDir
```

Дождитесь `READY`; адрес находится в generated manifest. Launcher создаёт отдельные volumes и учётные записи, собирает frontend с `NEXT_PUBLIC_APP_ENV=test` и `NEXT_PUBLIC_SYNTHETIC_DEMO=true`. Bootstrap публикует вымышленные данные 12 регионов Казахстана через настоящий backend; pipeline рассчитывает прогноз без ручной вставки MAE.

[Demo runbook](docs/runbooks/DEMO.md) описывает OIDC/browser-проверку и безопасную остановку. Его прежний seed отличается: для приведённого пути используйте только `scripts.local_demo.bootstrap`, не смешивайте наборы. Пароли, realm, `.env`, tokens и runtime-файлы не публикуются. Эти команды здесь проверены по исходникам, **не запущены заново**.

## Ограничения и дальнейшие шаги

Контур использует синтетические исторические данные, не текущую медицинскую статистику. Качество на реальных данных и публичное развёртывание не подтверждены. Область прогноза ограничена GLOBAL-потоком направлений.

**IMAGE_SECURITY=FAIL, SECURITY_ADMISSION=FAIL; production readiness не заявляется.** [Исторический image scan](docs/security/CURRENT_IMAGE_FINDINGS.md) обнаружил по 44 HIGH / 0 CRITICAL в backend, worker и MLflow; fixed versions тогда отсутствовали. Это не новый scan текущих образов.

Следующие шаги: повторный acceptance точного SHA, устранение известных frontend/browser отказов, проверка ресурсов развёртывания и отдельное закрытие security findings. Реальные медицинские данные и production-эксплуатация требуют отдельного допуска.
