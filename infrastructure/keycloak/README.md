# Keycloak — конфигурация области

MedSignal не аутентифицирует пользователей и не хранит пароли. Аутентификацию выполняет Keycloak по OIDC ([ADR-0009](../../docs/ADR/0009-keycloak-oidc-authentication.md)).

## Файл области

`realm-medsignal-dev.json` предназначен **исключительно для локальной разработки**. Он импортируется автоматически при запуске Keycloak в режиме `start-dev`.

> **Не импортировать этот файл ни в одну общую среду.** Для dev-стенда, staging и production область создаётся отдельно, с собственными клиентами, собственными секретами из внешнего хранилища и реальными пользователями, заведёнными администратором.

## Что содержит область

| Объект | Назначение |
|---|---|
| Роли `ADMIN`, `HEALTH_AUTHORITY`, `REGIONAL_ANALYST`, `HOSPITAL_MANAGER`, `HOSPITAL_ANALYST` | Роли системы. Приходят в токене в `realm_access.roles` |
| Клиент `medsignal-frontend` | Публичный клиент браузера: код авторизации с PKCE, без секрета |
| Клиент `medsignal-api` | Получатель токена. Своих потоков входа не имеет |
| Клиент `medsignal-dev-cli` | Служебный клиент для автоматической проверки фундамента |

Пользователей-людей в файле нет намеренно: создавать учётные записи с паролями в репозитории недопустимо.

## Клиент `medsignal-dev-cli`

Существует для одной задачи: получить действительный токен в автоматической проверке, не поднимая браузерный вход.

Его секрет содержит маркер `local_dev_only` — тот же, который backend отвергает при любом значении `APP_ENV`, кроме `local`. Клиент создаётся только этим файлом, а файл монтируется только локальной конфигурацией Docker Compose.

Получить токен:

```bash
make token
```

## Аудитория токена

Оба клиента, выпускающих токены, имеют отображатель `oidc-audience-mapper`, добавляющий `medsignal-api` в claim `aud`. Без него проверка аудитории на стороне backend была бы декоративной: Keycloak по умолчанию не кладёт в `aud` имя защищаемого ресурса.

## Раздельные адреса

| Параметр | Значение в локальной среде | Назначение |
|---|---|---|
| `OIDC_ISSUER` | `http://localhost/auth/realms/medsignal` | Публичный издатель, сверяется с claim `iss` |
| `OIDC_INTERNAL_BASE_URL` | `http://keycloak:8080/auth/realms/medsignal` | Внутренний адрес для загрузки ключей |

Браузер видит Keycloak через обратный прокси по адресу `/auth/`, а backend обращается к нему по имени сети контейнеров. Издатель в токене соответствует первому, ключи загружаются по второму. Смешение этих адресов даёт либо неработающую проверку, либо приём токена с чужим издателем.

## Переход к общей среде

1. Создать область вручную либо отдельным файлом без служебного клиента.
2. Секреты клиентов выдать из внешнего хранилища, не из файла в репозитории.
3. Включить требование HTTPS (`sslRequired: all`).
4. Завести пользователей и назначить им роли.
5. Задать области данных на стороне MedSignal: роли приходят от провайдера, область разрешается приложением (PHASE 2).
