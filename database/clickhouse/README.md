# Миграции ClickHouse

ClickHouse не имеет встроенного механизма миграций, поэтому изменения схемы хранятся нумерованными файлами и применяются по порядку. Применённые версии фиксируются в таблице `schema_migrations`.

Файлы из этого каталога монтируются в `/docker-entrypoint-initdb.d` и выполняются при первой инициализации контейнера. Для применения к уже работающей базе используется `make migrate`.

Таблицы временных рядов — метрики, очереди, направления, отказы, пролеченные случаи, прогнозы — появляются в PHASE 3. Их схема зависит от фактической структуры выгрузок и определяется после Data Audit ([ADR-0007](../../docs/ADR/0007-data-audit-before-ml-target.md)).

Принципы организации таблиц зафиксированы в [DATABASE.md](../../docs/DATABASE.md#4-таблицы-clickhouse): партиционирование по месяцу наблюдения, ключ сортировки начинается с организации, предагрегаты для дашборда, каждая запись хранит `import_id` и `contract_version`.
